抓流 首选
钩住播放器，把它已经解密好的码流直接存下来。
优点
  • 无损、不重编码，画质和源站一样
  • 省 CPU —— 存的是码流，不是重新画一遍
  • 页面上没有多余的东西（不是录屏）
缺点
  • 实时：视频多长就得播多长（用浏览器倍速播放能快一些）
  • 要刷新一次页面（但会接着当前进度继续，不用重看）
  • 播放器必须走 MSE；老式直链播放抓不到
录制 兜底
抓不到地址时，采集标签页画面重新编码成 MP4。
优点
  • 几乎什么都能录到，不需要解析地址
  • 边录边落盘，录多长都不吃内存
缺点
  • 是重新编码：画质有损，画面里会带上播放器自己的一层 UI
  • 必须实时 —— 播多久就得录多久，不能快进
  • 录制期间标签页被切走 / 锁屏，那几段没有画面
拿不准就先点抓流；它失败了再点录制。两者产物都在「管理」里。

抓流的数据全在内存里，本扩展按 32 GB 内存的机器设计：600 MB 阈值 ≈ 收尾合并时 峰值 1.8 GB。内存小的机器建议把上面两项调小（自动保存 5 分钟 / 自动切段 300 MB）， 或者干脆用「录制」。
普通视频（一集到不了 600 MB）用不到「自动切一段」；0.2.1 及更早的版本上， 一旦触发切段，第二段会没有声音（0.2.2 已修）。
