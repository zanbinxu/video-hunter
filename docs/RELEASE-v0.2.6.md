# Video Hunter 0.2.6 发布说明

## 概述

**Video Hunter 0.2.6** 是针对 MSE 抓流在各类极端场景（4K 超高清流、动态变码率 / 中途换容器、单页 SPA 连播、2x~12x 高倍速推流、浏览器私有存储写满）下的一次**全链路深度重构与稳定性强化版本**。

本版彻底解决了 WebM 中途重发 init / 字节错位导致的丢帧、大文件切段的缝隙、单页 SPA 连播的换集切段与单集标题、录制卡片状态不同步、倍速抓流时媒体时长偏小，以及**换页 / 换集后视频轨被整轨误清洗**等全部核心问题。

---

## 主要变更与修复

### 1. MSE 抓流：换页 / 换集后视频轨不再被整轨清洗（本版核心修复）

- **现象**：启动抓流后刷新页面（或站点换集）时，产物里**只剩一个 813 字节的初始化段，视频媒体分片一段都没进去**，收尾直接失败（界面提示「抓到的 1 条轨里没有可用视频轨」）；音频轨却是完整的。抓流端本身没有丢数据 —— 内容脚本如实上报了收到的每一段。
- **根因**：起播记忆预取的清洗逻辑（`cleansePrefetchBeforeRewind`）**没有做轨道隔离**。当后到的音频分片（时间轴从 0 开始）与已经攒下的视频分片（时间轴已到 10 秒）做比对时，被误判成「播放器又去预取了上次的位置」，于是把**当时缓冲区里所有非初始化分片清空** —— 连同整条视频轨一起清掉了。
- **修法**：预取比对与清洗严格按**轨道**隔离（按内容类型 / SourceBuffer 归组，音频只和音频比、视频只和视频比），清洗时只丢弃当前轨道的脏分片，**保留其它轨道的正常分片和所有初始化段**；同时把该处 `timescale` 的兜底从错误的 `1000` 改为按轨道取值（视频 90000 / 音频 48000）。
- **顺带修掉的两处联动问题**：
  - **自动切段被误判成过渡噪声**：按体积阈值触发的自动切段（`reason === 'size'`）不再走「数据太小 = 换集残留、跳过保存」那条规则，阈值该怎么切就怎么切；
  - **切段后收尾的产物信息缺失**：缓冲区已空、前面已经切过段的收尾分支，现在会完整回传最新一段产物的 `fileName` / `size` / `mediaSeconds` / 提示信息，不再让界面（和调用方）拿到一个空文件名。
- **实测**：修复前离屏文档里视频轨是 `1 段 / 813 字节`、整套浏览器端到端 **20 项失败**；修复后视频轨 `7 段 / 981,164 字节`、端到端 **0 失败**。

### 2. WebM 容错与全流程丢帧根治
- **中途重发 init 容错**：遇到第二份 init 时不再盲从过期的 Segment 长度，逐项跳过子元素后在下一个 Cluster 处恢复读取，杜绝后半段画面被整段吞掉（实测产物从只有约 75 帧恢复到 **150 帧全覆盖**）；
- **字节流错位自动救回**：对 Cluster 做严格双校验（时间戳子元素 + 合法元素头），跳过错位脏数据后继续读，后续上百兆画面全面救回；
- **同轨中途换容器**（如 WebM/VP9 换为 fMP4/AV1）：收到每一段自动嗅探容器，按「流 + 容器」细分归组独立解析，保留更长有效轨道；
- **主世界钩子分块让出**：`appendBuffer` 同步极速内存快照，base64 编码挪进微任务、48KB 分块让出主线程，彻底消除刷新后首抓导致的播放器卡死转圈。

### 3. 大文件切段零缝隙与首份安全快照
- **残余分片无损交接**：切段时提取尚未送入 muxer 的残余分片（remainder），平滑移交到下一段头部，消除切段交界处的时间轴缝隙与画面跳跃；
- **连续分片最大间隔放宽到 30 秒**（`maxGapTicks = timescale × 30`）：倍速播放、高倍速快进、长 GOP 分片都不会被误判成断流而重新对齐；
- **10 秒首份安全快照**：抓流开始后前 10 秒即落地第一份兜底文件，之后按设定间隔（如 5 分钟）滚动覆盖，确保突发断电或崩溃时随时有可用产物。

### 4. 单页播放列表（SPA）平滑换集与单集标题抓取
- **SPA 换集无感切段**：针对 URL 和页面都不刷新的单页连播站点，监听集数切换与媒体时间戳归零，换集前自动保存第一集，缓冲自动归位；
- **单集独立真实标题提取**：换集时抓取当前活跃播放项的真实集数与标题，产物按各集独立命名；
- **第二集自动回跳开头**：换集后自动把进度拉回开头录制，并丢弃换集瞬间的过渡残片（判据：数据量 < 1.5 MB 且时长 < 5 秒），杜绝只有几 KB 的幽灵文件。

### 5. 精准统计抓流视频内容时长（支持 2x~12x 极速推流）
- **解耦播放器当前播放进度**：「抓取内容」严格绑定内存中实际捕获分片的真实媒体时长，不再受播放器当前进度干扰；
- **底层解析 fMP4 时间基与 Sample 时长**：直接解析 `sidx` box 中的真实 `timescale`，并统计 `trun`/`tfhd` 中 sample 的实际 `durationTicks`；
- **修正 1000 默认 timescale 缺陷**：彻底废除 1000 错误兜底，默认按标准 90000（视频）/ 48000（音频）计算，确保 2x、3x、6x、9x、12x 高倍速下内容时长精准累计；
- **中途起播 Init Segment 自动重放**：用户中途才开启抓流时，`mse-hook` 自动重放之前缓存的初始化段（`__vhInit`），保障解码参数与时间基正确。

### 6. 悬浮录制卡片 1 秒动态刷新与 UI 排版优化
- **1 秒高频动态刷新**：卡片实时刷新「录制用时」、「抓取内容时长」、「内存缓冲区大小」与「磁盘快照大小」；
- **统一时间格式化**：时长格式统一支持 2 位数小时（如 `00:03:12`），支持长视频展示；
- **长标题换行完整呈现**：去除截断限制，完整显示视频标题；精细化文件列表标签与换集提示。

### 7. 数据安全出口与重试（零数据丢失）
- **写盘失败数据不丢**：浏览器私有存储写满导致落盘失败时，已抓到的分片**继续留在内存里**，界面明确写着「数据还在、别关标签页」，并给出「重试保存」与「放弃这一份」两个真实出口；
- **清出空间即可续存**：到管理页删掉旧的已导出产物后点「重试保存」，产物正常落盘；
- **收尾信息全透明**：切段后的收尾会回传产物文件名、体积、时长与转码警告，不再出现「明明存好了、界面却说不知道」的情况。

## 安装与使用

1. **开发者模式加载（推荐）**：
   - 打开 Chrome / Edge 浏览器，访问 `chrome://extensions`；
   - 开启右上角「**开发者模式**」；
   - 点击左上角「**加载已解压的扩展程序**」，选择解压后的目录 `dist/video-hunter-0.2.6` 即可。

2. **直接安装 zip**：
   - 下载下方的 `video-hunter-0.2.6.zip` 压缩包解压后加载，或直接分发使用。
